# Refactor Plan for Version 0.1: Stabilization and Extensibility

**Date**: 2026-01-09
**Goal**: Refactor the organically-grown g8aural app for maintainability, testability, and extensibility before implementing the pitch detection feature
**Status**: Planning phase

---

## Executive Summary

The g8aural app has grown organically through 7 major feature phases, resulting in a well-functioning but increasingly complex codebase. The main pain point is `app.py` with a 343-line server function mixing multiple concerns. This refactor prepares for version 0.1 stability and the upcoming pitch detection feature.

**Key Metrics**:
- Current: 546 lines in app.py, 343 in single server function
- Music theory modules: Well-structured (6 files, 2,139 lines total)
- Test coverage: 43 backend tests, 0 UI tests
- Target: Reduce complexity, improve testability, enable tab-based architecture for pitch detection

---

## I. Current State Analysis

### Strengths to Preserve
1. ✅ Clean separation: music theory engine vs web app
2. ✅ music21-based implementation (professional-grade)
3. ✅ Configuration-driven multi-grade support
4. ✅ Comprehensive backend tests (43 tests, 100% passing)
5. ✅ Well-documented architecture (CLAUDE.md, architecture docs)

### Pain Points to Address
1. ❌ app.py server function too large (343 lines, multiple concerns)
2. ❌ Flat reactive state (13 individual values, no grouping)
3. ❌ Global generator variable with `global` keyword
4. ❌ Long functions (`handle_guess`: 86 lines, `fetch_new_cadence`: 48 lines)
5. ❌ Repeated code patterns (button handlers, feedback updates, UI messages)
6. ❌ Zero UI/integration tests
7. ❌ No test fixtures or shared test utilities

---

## II. Refactoring Strategy

### Guiding Principles
1. **Incremental refactoring**: Small, testable changes
2. **Preserve functionality**: Zero breaking changes to user experience
3. **Enable extensibility**: Prepare for pitch detection tab architecture
4. **Improve testability**: Extract testable functions, add UI tests
5. **Maintain performance**: No regression in generation speed

### Non-Goals (Out of Scope for v0.1)
- ❌ Refactor music theory modules (already well-structured)
- ❌ Change UI appearance or user experience
- ❌ Implement pitch detection feature (separate project)
- ❌ Optimize performance (already acceptable)

### Phase 3: Create State Management Module (Priority: High, Effort: 3-4 hours)

**Objective**: Group related reactive state and create state management helpers

**Files to Create**:
- `state/game_state.py` - Game state dataclasses and helpers

**Changes**:
1. Create `state/` directory
2. Define dataclasses for grouped state:
   ```python
   from dataclasses import dataclass
   from typing import Optional, List
   from shiny import reactive

   @dataclass
   class ProgressionState:
       """Groups all data about the current progression"""
       progression: reactive.Value  # MIDI notes
       note_names: reactive.Value
       chord_symbols: reactive.Value
       cadence_type: reactive.Value
       key: reactive.Value

       @staticmethod
       def create():
           """Factory function to create initialized state"""
           return ProgressionState(
               progression=reactive.Value(None),
               note_names=reactive.Value(None),
               chord_symbols=reactive.Value(None),
               cadence_type=reactive.Value(None),
               key=reactive.Value(None)
           )

       def set_all(self, progression, note_names, chord_symbols, cadence_type, key):
           """Atomic update of all progression data"""
           self.progression.set(progression)
           self.note_names.set(note_names)
           self.chord_symbols.set(chord_symbols)
           self.cadence_type.set(cadence_type)
           self.key.set(key)

       def clear(self):
           """Reset all to None"""
           self.set_all(None, None, None, None, None)

   @dataclass
   class FeedbackState:
       """Groups feedback-related state"""
       message: reactive.Value
       type: reactive.Value  # "info", "error", "success"

       @staticmethod
       def create():
           return FeedbackState(
               message=reactive.Value(""),
               type=reactive.Value("info")
           )

       def set(self, message: str, feedback_type: str = "info"):
           """Atomic update of feedback message and type"""
           self.message.set(message)
           self.type.set(feedback_type)

   @dataclass
   class GameFlowState:
       """Groups game flow state"""
       state: reactive.Value  # "initial", "ready", "guessing", "correct", "hint_shown"
       has_played: reactive.Value
       is_playing: reactive.Value
       disabled_buttons: reactive.Value

       @staticmethod
       def create():
           return GameFlowState(
               state=reactive.Value("initial"),
               has_played=reactive.Value(False),
               is_playing=reactive.Value(False),
               disabled_buttons=reactive.Value([])
           )

   @dataclass
   class GradeState:
       """Groups grade-related state"""
       level: reactive.Value
       restored: reactive.Value

       @staticmethod
       def create(default_level: int = 6):
           return GradeState(
               level=reactive.Value(default_level),
               restored=reactive.Value(False)
           )
   ```

3. Update app.py to use grouped state:
   ```python
   from state.game_state import ProgressionState, FeedbackState, GameFlowState, GradeState

   def server(input, output, session):
       # Grouped reactive state
       progression_state = ProgressionState.create()
       feedback_state = FeedbackState.create()
       game_flow = GameFlowState.create()
       grade_state = GradeState.create()

       # Use grouped state throughout handlers
       progression_state.set_all(midi, names, symbols, cadence, key)
       feedback_state.set("Correct!", "success")
   ```

**Benefits**:
- Reduces 13 individual reactive values to 4 grouped objects
- Atomic updates prevent inconsistent state
- Clear ownership and responsibility for state
- Helper methods reduce boilerplate

**Testing**:

- Integration tests to verify state updates work correctly

   # handlers/game_logic.py

   def generate_new_cadence(generator, grade_level: int, allowed_cadences):
       """Generate a new cadence progression"""
       cadence_type = random.choice(allowed_cadences)
       progression = generator.generate_progression(cadence_type)
       midi = generator.progression_to_midi(progression)
       note_names = generator.progression_to_note_names(progression)
       symbols = generator.progression_to_symbols(progression)
       key = generator.get_progression_key(progression)
       return {
           'cadence_type': cadence_type,
           'progression': midi,
           'note_names': note_names,
           'symbols': symbols,
           'key': key
       }

   async def initialize_new_cadence(

       progression_state,
       feedback_state,
       game_flow,
       cadence_data

       # Update state
       progression_state.set_all(

           cadence_data['note_names'],
           cadence_data['symbols'],
           cadence_data['cadence_type'],

       game_flow.state.set("ready")
       game_flow.has_played.set(False)
       game_flow.disabled_buttons.set([])
       feedback_state.set("Listen and identify the cadence", "info")

       # Update UI
       await session.send_custom_message("updateButtonStates", {
           "enableAll": True,
           "showNext": False,
           "showHint": True
       })

### Phase 5: Eliminate Global State (Priority: High, Effort: 2 hours)

**Objective**: Remove global generator variable, use reactive value or dependency injection

**Changes**:
1. Replace global generator with reactive value:
   ```python
   # In server function
   from config.app_config import GENERATOR_CONFIG
   from modules.music_theory.progression import ChordProgressionGenerator

   # Create reactive generator
   generator = reactive.Value(
       ChordProgressionGenerator(**GENERATOR_CONFIG[6])
   )

   # When grade changes, update generator
   @reactive.Effect
   @reactive.event(input.grade_slider)
   async def _():
       if not grade_state.restored():
           return

       new_grade = int(input.grade_slider())
       if new_grade == grade_state.level():
           return

       # Update generator (no global keyword needed)
       config = GENERATOR_CONFIG[new_grade]
       generator.set(ChordProgressionGenerator(**config))

   # Use generator in handlers
   async def fetch_new_cadence():
       gen = generator()  # Get current generator
       cadence_data = generate_new_cadence(
           gen,
           grade_state.level(),
           CADENCE_TYPES_BY_GRADE[grade_state.level()]
       )
       # ... rest of logic
   ```

**Benefits**:
- Eliminates `global` keyword (code smell)
- Prevents potential race conditions
- Generator is now part of reactive system
- Easier to test (can inject mock generator)

**Testing**:
