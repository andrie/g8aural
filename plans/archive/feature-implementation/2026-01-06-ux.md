# UI/UX Improvements Plan
**Date:** 2026-01-13
**Status:** Planning

## Overview
This plan covers four UI/UX improvements to make the Grade 8 Aural Cadence Training application more intuitive and provide better feedback to users.

## Current State Analysis

### UI Structure
The current UI layout (from top to bottom):
1. Header with title
2. Control section: "Play Cadence" + "Show Hint" buttons
3. Answer section: 4 cadence buttons (Perfect, Plagal, Imperfect, Interrupted)
4. Feedback section: Alert messages
5. Notation section: Staff notation (hidden until needed)
6. Next section: "Next Cadence" button (hidden until needed)

### Current Behavior
- When user guesses correctly: Shows success message, displays notation, shows "Next Cadence" button
- When user guesses incorrectly: Shows error message, allows retry on all buttons
- When hint is shown: Displays notation, shows "Next Cadence" button, disables answer buttons
- "Show Hint" button is always visible once cadence is played

### State Management
State tracked in Python reactive values:
- `game_state`: "initial" → "ready" → "guessing" → "correct" / "hint_shown"
- `has_played`: Whether user has heard the cadence
- Answer attempts tracked implicitly (wrong answers re-enable buttons)

Button state management via JavaScript (`notation.js:updateButtonStates`):
- `playEnabled`: Enable/disable play button
- `answersEnabled`: Enable/disable all answer buttons
- `nextVisible`: Show/hide next button
- `showNotation`: Show/hide notation section

## Requested Changes

### 1. Move "Next Cadence" Button Above Staff Notation
**Current:** Next button appears at the very bottom
**Desired:** Next button appears above the staff notation

**Rationale:** Users should see the next button immediately after answering correctly, without scrolling past the notation.

### 2. Hide "Hint" Button After Correct Answer
**Current:** Hint button remains visible even after correct answer
**Desired:** Hint button disappears when user answers correctly

**Rationale:** The hint is no longer needed once the correct answer is given.

### 3. Add Visual Feedback on Cadence Buttons
**Current:** Buttons show no persistent state after clicking
**Desired:** After clicking a button, display checkmark (✓) for correct or cross (✗) for incorrect

**Rationale:** Provides clear visual feedback about which answer was selected and whether it was correct.

### 4. Disable Wrong Answer Buttons
**Current:** After wrong answer, all buttons remain enabled
**Desired:** After wrong answer, disable that specific button (but keep others enabled)

**Rationale:** Prevents user from selecting the same wrong answer repeatedly.

## Implementation Plan

### Phase 1: Reorder UI Elements (Move Next Button)
**Files to modify:** `app.py`

**Changes:**
1. Move "Next Cadence" button HTML block from bottom (lines 84-93) to before notation section (before line 77)
2. Keep button initially hidden with `style="display: none;"`
3. Test that button still shows/hides correctly via JavaScript

**Testing:**

- Verify next button appears above notation after showing hint
- Verify button doesn't interfere with notation rendering

### Phase 2: Hide Hint Button After Correct Answer
**Files to modify:**
- `app.py` (Python logic)
- `notation.js` (JavaScript button state management)

**Changes in app.py:**
1. Add new state message to `updateButtonStates` calls: `hintVisible: bool`
2. When correct answer is given (lines 236-242), set `hintVisible: False`
3. When hint is shown (lines 308-314), keep `hintVisible: True` (already shown)
4. When new cadence is fetched (lines 140-145), set `hintVisible: True` (reset)

**Changes in notation.js:**
1. Update `updateButtonStates` function to handle `hintVisible` state
2. Show/hide hint button: `document.getElementById("hint_btn").style.display = states.hintVisible ? "block" : "inline-block"`

**Testing:**
- Play cadence → hint button should be visible
- Answer correctly → hint button should disappear
- Click "Next Cadence" → hint button should reappear for new cadence

### Phase 3: Add Checkmark/Cross Emoji Feedback
**Files to modify:**
- `app.py` (Python logic to track which button was clicked)
- `notation.js` (JavaScript to add emoji to button text)

**Implementation approach:**

**Option A: Server-side button text update (Simpler)**
- Python tracks which button was clicked and result (correct/incorrect)
- Send custom message to JavaScript with button ID and emoji
- JavaScript updates button text: "Perfect ✓" or "Plagal ✗"

**Option B: Client-side tracking (More responsive)**
- When button clicked, immediately send guess to Python
- Python responds with result
- JavaScript updates button text based on result

**Recommended: Option A** (cleaner separation of concerns)

**Changes in app.py:**
1. In `handle_guess` function, after validation:
   - If correct: Send message `updateButtonFeedback` with `{buttonId: "perfect_btn", emoji: "✓", result: "correct"}`
   - If incorrect: Send message `updateButtonFeedback` with `{buttonId: "plagal_btn", emoji: "✗", result: "incorrect"}`
2. On new cadence, send message to clear all button emojis

**Changes in notation.js:**
1. Add new message handler: `Shiny.addCustomMessageHandler("updateButtonFeedback", ...)`
2. Handler updates button text:
   ```javascript
   const btn = document.getElementById(message.buttonId);
   const originalText = btn.getAttribute("data-original-text") || btn.textContent;
   if (!btn.hasAttribute("data-original-text")) {
       btn.setAttribute("data-original-text", originalText);
   }
   btn.textContent = `${originalText} ${message.emoji}`;
   ```
3. Add message handler to clear emojis: restore `data-original-text` values

**Testing:**
- Click correct button → should show checkmark immediately
- Click wrong button → should show cross immediately
- Click "Next Cadence" → emojis should clear for new question

### Phase 4: Disable Wrong Answer Buttons
**Files to modify:**
- `app.py` (Python logic to track wrong answers)
- `notation.js` (JavaScript to disable specific buttons)

**Implementation approach:**
Track wrong answers in Python, send list of disabled button IDs to JavaScript.

**Changes in app.py:**
1. Add new reactive value: `disabled_buttons = reactive.Value([])`
2. In `handle_guess` function:
   - If incorrect: Add button ID to disabled list
   - Send message: `updateButtonStates` with new field `disabledButtons: ["plagal_btn"]`
3. When correct answer given: Keep wrong buttons disabled (no change needed)
4. On new cadence (`fetch_new_cadence`): Reset `disabled_buttons.set([])`, send empty list

**Changes in notation.js:**
1. Update `updateButtonStates` function to handle `disabledButtons` array
2. Implementation:
   ```javascript
   if (states.disabledButtons !== undefined) {
       states.disabledButtons.forEach(btnId => {
           const btn = document.getElementById(btnId);
           if (btn) btn.disabled = true;
       });
   }
   ```
3. When clearing for new cadence, re-enable all buttons (already handled by `answersEnabled: false` then `true`)

**Edge case handling:**
- If user shows hint after wrong guesses, keep wrong buttons disabled
- If user plays cadence again after wrong guess, wrong buttons stay disabled
- Only "Next Cadence" resets the disabled state

**Testing:**
- Click wrong button → button should disable and show ✗
- Click another wrong button → both should be disabled
- Click correct button → wrong buttons stay disabled, correct shows ✓
- Click "Next Cadence" → all buttons re-enabled for new question

### Phase 5: Integration Testing
**Test scenarios:**

1. **Happy path (correct first try):**
   - Play cadence
   - Click correct button → shows ✓, hint button hides, notation appears with next button above it
   - Click next cadence → new question, all buttons enabled, hint visible, emojis cleared

2. **Wrong then correct:**
   - Play cadence
   - Click wrong button → shows ✗, button disables
   - Click another wrong button → shows ✗, button disables
   - Click correct button → shows ✓, hint hides, notation shows, next button appears
   - Click next cadence → all buttons reset

3. **Use hint:**
   - Play cadence
   - Click wrong button → shows ✗, button disables
   - Click "Show Hint" → notation shows, hint button stays visible (already used), next button above notation
   - Click next cadence → reset

4. **Multiple wrong answers:**
   - Play cadence
   - Click three wrong buttons in sequence
   - All should show ✗ and disable
   - Only one correct button remains enabled
   - Click correct button → success

## Technical Considerations

### State Synchronization
- Button emojis and disabled states must stay in sync between Python and JavaScript
- Use Python as source of truth, JavaScript only renders state
- Clear all state on new cadence to prevent stale UI

### Button Text Management
- Store original button text in `data-original-text` attribute
- Append emoji without replacing original text
- Clear emoji by restoring original text

### CSS Considerations
- Disabled buttons already have proper styling (`opacity: 0.4`, line 103-108 in styles.css)
- May need to adjust button text sizing if emojis make buttons wider
- Consider adding specific CSS for correct/incorrect button states:
  ```css
  .cadence-btn.correct { border-color: green; }
  .cadence-btn.incorrect { border-color: red; }
  ```

### Performance
- Minimal performance impact (simple DOM updates)
- No additional server round-trips (state sent with existing messages)

## Risk Assessment

### Low Risk
- Moving HTML elements (Phase 1): Simple reordering
- Hiding hint button (Phase 2): Simple visibility toggle

### Medium Risk
- Adding emoji feedback (Phase 3): Text manipulation could cause layout shifts
- Disabling wrong buttons (Phase 4): Must ensure correct buttons remain clickable

### Mitigation
- Test thoroughly on different screen sizes (responsive design)
- Ensure button grid layout doesn't break with longer text
- Add fallback if emoji rendering fails (use text "✓" / "✗")

## Rollback Plan

2. Git commit after each phase for easy reversion
3. JavaScript changes are isolated to `notation.js` (easy to revert)
4. Python changes are in `app.py` (well-documented)
